    TP 🧮 Piles, files et notations polonaises⚓︎

    Cadre du TP

    • Durée : 2 h (parties 1 à 4) + prolongements (parties 5 et 6)
    • Prérequis : cours Structures de données linéaires : piles, files, POO
    • Objectifs :
      • utiliser l'interface d'une pile et d'une file sans se soucier de leur implémentation ;
      • choisir la bonne structure (LIFO ou FIFO) selon le traitement à réaliser ;
      • concevoir une classe Calculatrice qui compose des objets Pile et File.
    • Fichiers à produire : structures.py, calculatrice.py

    0. 📜 Trois façons d'écrire un calcul⚓︎

    Nous écrivons les calculs en notation infixe : l'opérateur est entre ses opérandes, 3 + 4. Cette notation a un défaut : elle a besoin de parenthèses et de règles de priorité pour lever les ambiguïtés (3 + 4 * 5 vaut 23, pas 35).

    En 1924, le logicien polonais Jan Łukasiewicz propose de placer l'opérateur devant ses opérandes : c'est la notation polonaise (ou préfixe). Sa variante miroir, où l'opérateur est placé après, est la notation polonaise inversée (NPI, ou postfixe), popularisée par les calculatrices HP.

    Notation Position de l'opérateur (3 + 4) * 5
    infixe entre les opérandes ( 3 + 4 ) * 5
    polonaise (préfixe) avant les opérandes * + 3 4 5
    polonaise inversée (postfixe) après les opérandes 3 4 + 5 *

    À retenir

    Les notations préfixe et postfixe n'ont besoin ni de parenthèses, ni de règles de priorité : l'ordre des jetons suffit. C'est ce qui les rend si faciles à évaluer par une machine… avec une pile.

    Exercice 0 — à la main ✏️

      Infixe Préfixe NPI
      3 + 4 * 5
      ( 8 - 2 ) / ( 1 + 2 )

      5 1 2 + 4 * + 3 -

    2. Calculer la valeur de chacune de ces expressions.

    3. 7 2 - et 2 7 - donnent-elles le même résultat ? Que faut-il en déduire sur l'ordre des opérandes ?

    3 + 4 * 5 + 3 * 4 5 3 4 5 * + 23

    Question : dans le cours, empile utilisait insert(0, x) et depile utilisait pop(0). Ici on vous demande d'utiliser append(x) et pop(). Quel est l'intérêt ? Le reste du TP devra-t-il être modifié si l'on change d'avis ?

    🐍 Python
    class Pile:
    def __init__(self):
        self.data = []

    def est_vide(self):
        return len(self.data) == 0

    def empile(self, x):
        self.data.append(x)

    def depile(self):
        if self.est_vide():
            raise IndexError("Vous avez essayé de dépiler une pile vide !")
        return self.data.pop()

    def sommet(self):
        if self.est_vide():
            raise IndexError("Pile vide : pas de sommet !")
        return self.data[-1]

    def taille(self):
        return len(self.data)

    def __str__(self):
        s = "|"
        for k in self.data:
            s = s + str(k) + "|"
        return s


class File:
    def __init__(self):
        self.entree = Pile()
        self.sortie = Pile()

    def est_vide(self):
        return self.entree.est_vide() and self.sortie.est_vide()

    def enfile(self, x):
        self.entree.empile(x)

    def defile(self):
        if self.est_vide():
            raise IndexError("Vous avez essayé de défiler une file vide !")
        if self.sortie.est_vide():
            while not self.entree.est_vide():
                self.sortie.empile(self.entree.depile())
        return self.sortie.depile()

    def taille(self):
        return self.entree.taille() + self.sortie.taille()

    def __str__(self):
        s = "|"
        for k in reversed(self.sortie.data):
            s = s + str(k) + "|"
        for k in self.entree.data:
            s = s + str(k) + "|"
        return s

    append et pop() travaillent en fin de tableau, en temps constant \(O(1)\), alors que insert(0, x) et pop(0) décalent tous les éléments : \(O(n)\). Le reste du TP n'a pas à changer : il n'utilise que l'interface (empile, depile, sommet, est_vide, taille), jamais data. C'est l'encapsulation.

    Règle du jeu pour toute la suite

    Dans calculatrice.py, il est interdit d'écrire .data, .entree ou .sortie, et d'utiliser une liste Python à la place d'une pile ou d'une file. On ne passe que par l'interface.

    2. ✂️ Découper l'expression : une file de jetons⚓︎

    Une expression est une chaîne dont les jetons (nombres, opérateurs, parenthèses) sont séparés par des espaces : "3 4 + 5 *". Les jetons doivent être traités dans leur ordre d'arrivée : c'est une file.

print(jetons)             # |3|4|+|5|*|

    🐍 Python
    from structures import Pile, File

def tokenise(texte):
    jetons = File()
    for mot in texte.split():
        jetons.enfile(mot)
    return jetons

    3. 🥞 Évaluer une expression en NPI : la pile⚓︎

    Algorithme. On défile les jetons un par un :

    • si le jeton est un nombre, on l'empile ;
    • si le jeton est un opérateur, on dépile deux valeurs, on applique l'opérateur, on empile le résultat.

    À la fin, la pile contient une seule valeur : le résultat.

    Exercice 3.1 — à la main ✏️

    Dérouler l'algorithme sur 5 1 2 + 4 * + 3 - en donnant l'état de la pile après chaque jeton.

    Jeton lu Action Pile (sommet à droite)
    5 empile |5|
    1 empile |5|1|
    2 empile |5|1|2|
    + dépile 2 puis 1, empile 1 + 2 |5|3|
    4 empile |5|3|4|
    * dépile 4 puis 3, empile 3 × 4 |5|12|
    + dépile 12 puis 5, empile 5 + 12 |17|
    3 empile |17|3|
    - dépile 3 puis 17, empile 17 − 3 |14|

    Résultat : 14.

    🐍 Python
    class Calculatrice:
    def __init__(self):
        self.priorites = {"+": 1, "-": 1, "*": 2, "/": 2}

    def est_operateur(self, jeton):
        return jeton in self.priorites

    def applique(self, op, a, b):
        if op == "+":
            return a + b
        elif op == "-":
            return a - b
        elif op == "*":
            return a * b
        elif op == "/":
            if b == 0:
                raise ZeroDivisionError("Division par zéro !")
            return a / b
        else:
            raise ValueError(f"Opérateur inconnu : {op}")

    def evalue_npi(self, texte):
        jetons = tokenise(texte)
        pile = Pile()
        while not jetons.est_vide():
            jeton = jetons.defile()
            if self.est_operateur(jeton):
                b = pile.depile()      # opérande de droite
                a = pile.depile()      # opérande de gauche
                pile.empile(self.applique(jeton, a, b))
            else:
                pile.empile(float(jeton))
        return pile.depile()

    Exercice 3.3 — expressions mal formées 🛡️

    1. Que se passe-t-il avec c.evalue_npi("3 +") ? Avec c.evalue_npi("3 4") ?
    2. Modifier evalue_npi pour lever une ValueError au message explicite dans ces deux cas.

    "3 +" provoque une IndexError (pile vide) peu parlante ; "3 4" renvoie 4 sans signaler qu'il reste une valeur dans la pile.

    🐍 Python
        def evalue_npi(self, texte):
        jetons = tokenise(texte)
        pile = Pile()
        while not jetons.est_vide():
            jeton = jetons.defile()
            if self.est_operateur(jeton):
                if pile.taille() < 2:
                    raise ValueError(f"Opérande manquant pour '{jeton}'")
                b = pile.depile()
                a = pile.depile()
                pile.empile(self.applique(jeton, a, b))
            else:
                pile.empile(float(jeton))
        if pile.taille() != 1:
            raise ValueError("Expression mal formée")
        return pile.depile()

    4. 🔄 Évaluer une expression en notation polonaise (préfixe)⚓︎

    En préfixe, l'opérateur arrive avant ses opérandes : en lisant de gauche à droite, on ne peut pas calculer tout de suite. L'astuce : lire l'expression de droite à gauche, et appliquer le même algorithme qu'en NPI.

    Exercice 4 — evalue_prefixe

    1. Notre file ne se défile que dans un sens. Avec quelle structure peut-on inverser l'ordre de ses éléments ?
    2. Dérouler à la main l'évaluation de - * 2 + 3 4 5 lue de droite à gauche.
    3. Ajouter la méthode evalue_prefixe(self, texte). Attention : l'ordre des deux opérandes dépilés est-il le même qu'en NPI ?
    🐍 Python
    assert c.evalue_prefixe("+ 3 4") == 7
assert c.evalue_prefixe("- 7 2") == 5
assert c.evalue_prefixe("* + 3 4 5") == 35
assert c.evalue_prefixe("- * 2 + 3 4 5") == 9
assert c.evalue_prefixe("/ - 8 2 + 1 2") == 2

    1. Une pile : on défile tout dans une pile, puis on dépile. Le dernier jeton entré sort en premier (LIFO).

    2.

    Jeton lu Pile (sommet à droite)
    5 |5|
    4 |5|4|
    3 |5|4|3|
    + dépile 3 puis 4, empile 3 + 4 → |5|7|
    2 |5|7|2|
    * dépile 2 puis 7, empile 2 × 7 → |5|14|
    - dépile 14 puis 5, empile 14 − 5 → |9|

    3. Comme on lit à l'envers, la première valeur dépilée est cette fois l'opérande de gauche.

    🐍 Python
        def evalue_prefixe(self, texte):
        jetons = tokenise(texte)
        inverse = Pile()
        while not jetons.est_vide():
            inverse.empile(jetons.defile())
        pile = Pile()
        while not inverse.est_vide():
            jeton = inverse.depile()
            if self.est_operateur(jeton):
                if pile.taille() < 2:
                    raise ValueError(f"Opérande manquant pour '{jeton}'")
                a = pile.depile()      # opérande de gauche
                b = pile.depile()      # opérande de droite
                pile.empile(self.applique(jeton, a, b))
            else:
                pile.empile(float(jeton))
        if pile.taille() != 1:
            raise ValueError("Expression mal formée")
        return pile.depile()

    5. 🚂 De l'infixe à la NPI : l'algorithme de la gare de triage⚓︎

    Pour que notre calculatrice accepte l'écriture habituelle, il faut convertir l'infixe en NPI. L'algorithme, dû à Edsger Dijkstra (1961), s'appelle shunting-yard (gare de triage). Il utilise une file et une pile en même temps :

    • une file sortie qui reçoit les jetons dans l'ordre NPI ;
    • une pile operateurs où les opérateurs attendent leur tour.
    flowchart LR
    E["File d'entrée<br/>3 + 4 * 5"] -- nombres --> S["File de sortie<br/>3 4 5 * +"]
    E -- "opérateurs, ( " --> P["Pile d'opérateurs"]
    P -- dépilement --> S

    Pour chaque jeton défilé :

    Jeton Action
    nombre on l'enfile dans sortie
    opérateur op tant que le sommet de la pile est un opérateur de priorité supérieure ou égale à celle de op, on le dépile vers sortie ; puis on empile op
    ( on l'empile
    ) on dépile vers sortie jusqu'à rencontrer (, que l'on dépile sans l'enfiler

    Quand il n'y a plus de jetons, on dépile tous les opérateurs restants vers sortie.

    Exercice 5.1 — à la main ✏️

    3 3
    + 3 +
    4 3 4 +
    * 3 4 + *
    ( 3 4 + * (
    2 3 4 2 + * (

    Ajouter à Calculatrice :

    • infixe_vers_npi(self, texte) qui renvoie la chaîne NPI correspondante ;
    • evalue_infixe(self, texte) qui renvoie la valeur de l'expression infixe (une ligne suffit !).

    Les parenthèses sont des jetons : elles sont entourées d'espaces.

    🐍 Python

    Questions

    1. Pourquoi la sortie est-elle une file et non une pile ?
    2. Que donnerait 8 - 2 - 1 si l'on remplaçait « supérieure ou égale » par « strictement supérieure » ?
    🐍 Python
        def infixe_vers_npi(self, texte):
        jetons = tokenise(texte)
        sortie = File()
        operateurs = Pile()
        while not jetons.est_vide():
            jeton = jetons.defile()
            if self.est_operateur(jeton):
                while (not operateurs.est_vide()
                       and self.est_operateur(operateurs.sommet())
                       and self.priorites[operateurs.sommet()] >= self.priorites[jeton]):
                    sortie.enfile(operateurs.depile())
                operateurs.empile(jeton)
            elif jeton == "(":
                operateurs.empile(jeton)
            elif jeton == ")":
                while not operateurs.est_vide() and operateurs.sommet() != "(":
                    sortie.enfile(operateurs.depile())
                if operateurs.est_vide():
                    raise ValueError("Parenthèse fermante en trop")
                operateurs.depile()        # on jette la "("
            else:
                sortie.enfile(jeton)
        while not operateurs.est_vide():
            op = operateurs.depile()
            if op == "(":
                raise ValueError("Parenthèse ouvrante jamais fermée")
            sortie.enfile(op)
        resultat = ""
        while not sortie.est_vide():
            resultat = resultat + sortie.defile() + " "
        return resultat.strip()

    def evalue_infixe(self, texte):
        return self.evalue_npi(self.infixe_vers_npi(texte))
    1. Les jetons doivent ressortir dans l'ordre où ils ont été produits : FIFO. Les opérateurs, eux, attendent et le dernier arrivé repart le premier : LIFO.
    2. On obtiendrait 8 2 1 - -, soit 8 − (2 − 1) = 7 au lieu de (8 − 2) − 1 = 5. Le « ou égale » traduit l'associativité à gauche de - et /.

        def npi_vers_infixe(self, texte):
        jetons = tokenise(texte)
        pile = Pile()
        while not jetons.est_vide():
            jeton = jetons.defile()
            if self.est_operateur(jeton):
                b = pile.depile()

    Exercice 6.4 — retour sur l'encapsulation

    Remplacer dans structures.py l'implémentation de File par celle à base d'une seule liste (append / pop(0)) vue en cours. Relancer tous les tests de calculatrice.py : que constate-t-on ? Pourquoi ?

    Bilan

    • Une pile sert à mettre en attente et à inverser : opérandes en attente d'un opérateur, opérateurs en attente de priorité, lecture à l'envers.
    • Une file sert à préserver l'ordre d'arrivée : jetons à lire, jetons produits.
    • Calculatrice n'utilise que l'interface de Pile et File : on peut changer leur implémentation sans toucher à une seule ligne de la calculatrice.
